# ProofMate 收敛式证据审查流程设计

日期：2026-09-26

## 目标

把当前“正文切六段并不断追加模型结果”的流程，改造成能够解释、迭代和收敛的证据审查闭环。用户上传材料后，应当看到可读主张、各自对应的证据、明确的模型处理顺序，以及每轮复核带来的真实变化。重复运行不能制造重复主张或虚高分数。

## 当前问题与根因

1. `buildImportedAudit` 按句号和换行切割提取文字，直接把前六段作为主张。Markdown 标题与 HTML 表格标签因此进入主张卡。
2. 同一文件切出的所有主张都关联整份文件对应的同一个证据项，所以切换主张时证据关系板内容近似相同。
3. OpenVINO 和 Qwen 的确认操作只按完整 statement 去重后追加。它们不会更新已有主张、合并近义主张、淘汰已解决问题或重算所有关系。
4. 分数主要由固定初始维度和人工确认时的固定加分决定，与当前主张、有效证据和冲突数量没有稳定对应关系。
5. 关系板展示长文本时缺少摘要边界和展开机制，累计内容会挤压布局并造成视觉噪声。

## 用户可理解的模型顺序

真实材料按以下固定顺序处理：

1. **文件读取层**：文本文件在浏览器读取；文本型 PDF 由 PDF.js 读取；图片和扫描 PDF 由 TextIn xParse OCR。该层只提取文字，不生成主张，也不进行证据判断。
2. **正文清洗层**：去除 Markdown 标题符号、围栏、链接语法和 HTML 标签，保留表格单元格的人类可读文字；按照标题、段落、页码和文件来源生成可定位片段。
3. **OpenVINO 端侧初审**：第一次模型处理。它从清洗后的片段中生成候选主张，并为每条主张返回原文依据、风险边界和补证建议。模型不可用时，产品只展示“材料片段待分析”，不得把片段冒充主张。
4. **人工入档**：用户确认候选后，系统把它们合并进档案。入档动作同时建立主张和来源片段的关系。
5. **Qwen 云端复核**：只处理尚未解决的主张及其相关证据，核对遗漏、冲突、外推边界和补证方向。云端模型不是重新对整份档案无限生成六条内容。
6. **重算与收敛**：每轮结果按稳定标识合并，重算状态、维度和总分。没有实质变化时明确显示“本轮无新增变化”，不会继续添加重复内容。

演示案例保留既有回放数据，但界面必须明确标注为样例；真实材料不得混用演示结论。

## 数据模型

### 材料片段

为证据增加稳定的来源信息：

- `sourceFingerprint`：文件名、大小、修改时间和类型形成的文件标识。
- `locator`：页码、标题或段落序号等可读位置。
- `content`：清洗后的完整片段。
- `excerpt`：用于卡片展示的短摘录。
- `extractionMethod`：browser-text、pdfjs、xparse-ocr 或 none。

### 主张

为主张增加审查生命周期信息：

- `fingerprint`：标准化后的主张文本，用于跨轮次合并。
- `origin`：openvino、qwen、human 或 demo。
- `reviewRevision`：最后一次发生实质变化的轮次。
- `evidenceIds`：只包含与该主张实际相关的证据片段。

主张文本在存储前必须经过纯文本清洗和长度限制。只有包含可验证陈述且拥有可定位依据的内容才能成为主张。

### 复核轮次

每一轮模型结果转成统一的变更集：

- `added`：此前不存在的新主张。
- `updated`：已有主张的风险、建议、状态或证据关系发生变化。
- `merged`：与已有主张近义，已并入原主张。
- `resolved`：证据已经闭环，不再进入下一轮。
- `unchanged`：没有新信息，不写入档案。
- `remaining`：下一轮仍需复核的主张数。

## 合并与去重规则

1. 先比较主张标准化文本：去除 Markdown/HTML、空白、标点和无意义前缀。
2. 完全相同的 fingerprint 必须更新原记录，不能新增。
3. 同一来源片段且核心数字、对象和结论一致的近义主张合并；风险和补证建议保留信息更完整的一版。
4. 同一证据通过 `sourceFingerprint + locator + excerpt` 去重。
5. 冲突结果更新原主张为 `conflict`；支持证据只把缺证主张提升为 `weak`，必须经过人工确认才能成为 `verified`。
6. 已 `verified` 的主张默认不进入下一次云端复核，除非新增冲突证据。
7. 一轮没有 added、updated、merged 或 resolved 时，轮次结束并显示已收敛。

## 评分规则

分数始终从当前档案派生，禁止固定加分：

- 覆盖度：拥有至少一条支持证据的主张占比。
- 一致性：无冲突主张占比，并对高重要度冲突加重扣分。
- 新鲜度：证据有明确时间信息或用户确认有效期的比例；未知时间不能假定为最新。
- 可复现性：拥有可定位原文、方法/参数/版本信息和人工确认关系的比例。

总分继续使用既有权重：覆盖度 35%、一致性 25%、新鲜度 15%、可复现性 25%。每次导入、模型入档、证据上传、人工确认和关系修改后统一重算。模型仅提供候选关系，不能直接把主张标记为已证实。

## 界面行为

### 主张索引卡

- 只显示清洗后的纯文字，不显示 Markdown/HTML 控制符。
- 两行摘要，超出部分省略；选中后在右侧完整显示。
- 显示来源模型和当前状态，帮助用户理解主张从哪里产生。
- 切换主张必须同步改变关系板和风险检查器。

### 证据关系板

- 只展示当前主张的关联证据。
- 卡片摘要限制为三至四行，提供“展开原文”。
- 默认最多展示四张卡；更多证据放入可滚动区域，并显示总数。
- 没有相关证据时显示缺口，不复用其他主张的证据。
- 支持、冲突、无关和待判断四类关系具有稳定排序和清晰标签。

### 模型运行区

- 明确写出“文件读取不是模型分析”。
- 真实材料第一次进入档案后，OpenVINO 是第一遍模型初审；Qwen 是可选的云端复核。
- 每次运行前显示输入范围，例如“复核 4 条未解决主张”。
- 每次运行后显示变更摘要：新增、更新、合并、解决和剩余数量。
- “确认并加入档案”只应用当前变更集；重复点击和重复运行保持幂等。
- 当已收敛时禁用无意义的再次入档按钮，但允许新增材料后重新复核。

### 原始材料区

- 默认展示清洗后的可读文字。
- 原始 Markdown/HTML 仅通过“查看原始内容”显式展开。
- PDF 原文件预览、提取方式、来源文件和定位信息保持可见。

## 错误处理

- PDF/OCR 失败：保留材料记录和失败原因，不生成虚假主张。
- OpenVINO 不可用：保留已提取正文，显示端侧初审未完成，不自动切换成演示结果。
- Qwen 失败或超时：档案不变，显示错误原因和本轮未应用。
- 模型输出格式异常：拒绝入档并展示可诊断错误，不把原始响应按换行切成主张。
- 某条结果缺少来源摘录：只能作为待定位提示，不计入有效支持证据。

## 实现边界

本次改造复用现有 React、OpenVINO 服务、Qwen 适配器、PDF.js 和 xParse，不引入新的运行时依赖。重点修改正文清洗、初始档案构建、统一复核合并器、派生评分和相关界面。演示案例数据结构向后兼容，已保存旧档案在加载时补齐缺省字段。

## 验收标准

1. 导入含 Markdown 标题和 HTML 表格的 PDF 后，主张卡不出现 `#`、`<table>`、`<td>` 等控制符。
2. 不同主张至少在有关联依据时显示各自不同的证据集合；无依据时显示缺口。
3. 首次进入真实档案时，界面明确说明目前只完成提取；运行 OpenVINO 后才出现模型候选主张。
4. 相同 OpenVINO 或 Qwen 结果连续确认两次，主张数和证据数不增加。
5. 第二次云端复核只发送未解决主张；若结果没有变化，显示已收敛且档案不变。
6. 新增支持、冲突或人工确认关系后，四项维度与总分从当前档案重新计算。
7. 关系板在桌面和移动尺寸都不截断关键控件，长内容可展开或滚动。
8. 使用真实 PDF 完成从上传、提取、端侧初审、入档、云端复核到再次复核的浏览器端流程。
9. 单元测试、组件测试、构建和浏览器端回归全部通过。
