# 真源 ProofMate：端云协同可信证据系统设计

## 1. 目标与定位

真源 ProofMate 是一件面向天猫 AI 黑客松高校挑战赛的完整 Web Demo，参赛赛道为“AI WORKS 效率进化”，同时响应阿里云特别赛题“基于 Qwen 大模型的科研提效、认知增强与研究范式革新”。

产品帮助学生和年轻研究者审计论文、竞赛项目、实验报告与答辩材料中的关键主张。它把散落在 PDF、Markdown、代码、表格和截图里的内容转化为“主张—证据—风险—修复”图谱，让用户在答辩前发现缺失证据、相互矛盾、时效过期和无法复现的问题。

参赛作品名称固定为：**真源：端云协同可信证据系统**。

首屏技术署名固定为：**天猫 AI 黑客松作品 · Qwen × OpenVINO**。这句话说明赛事归属和技术组合，不暗示天猫官方为产品背书。

## 2. 成功标准

1. 无 API Key、无本地模型时，评委打开项目即可通过内置样例走完整流程。
2. 用户能在 90 秒演示内完成：导入项目包、生成主张、查看证据图谱、发现风险、补充证据、看到健康度提升、导出答辩摘要。
3. 至少展示 6 条主张、10 个证据节点、4 类风险，以及一次补证前后的可量化变化。
4. 页面在 1440×900 和 390×844 下均可用，无明显溢出、遮挡或不可读内容。
5. 真实 Qwen 与 OpenVINO 接口可配置、可验证、不会把密钥写入仓库；缺少外部能力时明确显示演示模式，不伪造实时调用。
6. 提供初赛要求的封面、ZIP 作品包、AI 实践证据、体验说明、300 字内作品介绍和 300 字内技术说明。

## 3. 评审策略

- **创新性**：主张级证据图谱和“可修复风险”交互，不是又一个论文搜索或聊天机器人。
- **实用性**：聚焦学生论文、项目申报、竞赛答辩的最后一公里，输入就是用户已有材料。
- **完成度**：内置真实感样例、完整分析流程、可视化图谱、报告导出、配置面板和错误状态。
- **美观度**：采用天猫竞赛红、墨黑、暖白与少量青绿色，呈现“审计控制台”而非通用后台。
- **技术加分**：端侧 OpenVINO 负责隐私优先的本地语义索引与轻量推理，云端 Qwen 负责多模态理解和复杂核验。

## 4. 核心用户流程

### 4.1 首次进入

用户看到一句结果导向的主标题：“每个结论，都能找到它的证据。”首屏同时展示当前运行模式、隐私说明和“体验示例项目”主按钮。

### 4.2 导入与扫描

用户可拖入 PDF、Markdown、TXT、CSV、JSON 和常见图片，或直接载入内置的“校园节能 AI 项目”样例。系统先在端侧完成文件清单、文本解析、敏感信息提示与语义切片，再把允许上云的片段交给 Qwen 分析。

### 4.3 证据驾驶舱

主界面同时呈现：

- 项目证据健康度与四项分数；
- 主张列表及“已证实、待补证、有冲突、高风险”状态；
- 可交互的主张—证据图谱；
- 风险详情、原文定位和修复建议；
- 端侧与云端的本次处理轨迹。

### 4.4 补证闭环

用户选择一条证据不足的主张，添加一条新的实验记录。系统重新计算关联度和健康度，界面以可见动画展示风险被消除、分数上升和答辩准备度变化。

### 4.5 导出

系统生成可下载的 Markdown 答辩摘要，包含项目概述、核心主张、证据索引、剩余风险、建议回答和技术实践说明。浏览器打印可生成 PDF，不引入服务端文档依赖。

## 5. 技术架构

### 5.1 Web 应用

使用 React、TypeScript、Vite 和 CSS 构建单页应用。所有核心 Demo 数据和状态在浏览器端运行；文件内容不默认上传。Vitest 与 Testing Library 覆盖领域逻辑和关键交互。

### 5.2 端侧服务

Python FastAPI 服务暴露以下接口：

- `GET /health`：返回服务与模型状态；
- `POST /v1/local/analyze`：对文本片段进行本地语义分析；
- `POST /v1/local/embed`：生成端侧向量；
- `GET /v1/local/model`：返回模型名称、设备、量化方式与是否就绪。

默认模型为 **Qwen3-4B INT4 OpenVINO**，设备为 CPU。该模型约占数 GB，适配 Ryzen 7 5800H 与 14GB 内存；首次下载是可选步骤。服务未安装模型时返回明确的 `model_unavailable`，Web Demo 自动使用可审计的内置分析结果，而不是冒充模型输出。

### 5.3 云端适配器

前端只调用本地开发代理 `/api/qwen/analyze`。代理从环境变量 `DASHSCOPE_API_KEY` 读取密钥，并调用百炼兼容接口。未配置密钥时返回 `provider_not_configured`。仓库只提供 `.env.example`。

### 5.4 数据边界

- 原始文件和端侧索引默认不离开本机；
- 仅在用户启用 Qwen 后发送经过预处理的必要片段；
- Demo 模式、端侧模式和端云模式在 UI 中明确区分；
- 所有分析结果携带来源标识和时间戳。

## 6. 领域模型

```ts
type ClaimStatus = 'verified' | 'weak' | 'conflict' | 'missing';

interface EvidenceItem {
  id: string;
  title: string;
  kind: 'document' | 'code' | 'data' | 'image' | 'log';
  excerpt: string;
  source: string;
  confidence: number;
}

interface Claim {
  id: string;
  statement: string;
  status: ClaimStatus;
  importance: 'critical' | 'high' | 'medium';
  evidenceIds: string[];
  risk: string;
  repair: string;
}

interface ProjectAudit {
  id: string;
  name: string;
  score: number;
  dimensions: { coverage: number; consistency: number; freshness: number; reproducibility: number };
  claims: Claim[];
  evidence: EvidenceItem[];
  trace: Array<{ stage: 'device' | 'cloud'; label: string; detail: string }>;
}
```

健康度为四项维度加权结果：证据覆盖度 35%、一致性 25%、时效性 15%、可复现性 25%。所有显示分数均由领域函数计算，不能在组件中写死。

## 7. 样例故事

内置样例“校园节能 AI 项目”包含：项目说明、实验数据摘要、部署日志、模型卡片和现场照片描述。初始健康度约为 68 分，风险包括：节能 31% 的样本周期不足、模型准确率与报告数字冲突、部署日志缺少模型版本、隐私说明缺失。用户补充为期 30 天的对照实验后，系统把核心主张改为已证实，健康度提升到 80 分以上。

## 8. 视觉设计

- 色彩：`#ff1744` 竞赛红、`#0b0b0d` 墨黑、`#f4f0e8` 暖白、`#35d0ba` 验证绿；
- 字体：中文使用系统黑体栈，数字使用等宽字体；
- 版式：首屏强叙事，工作台使用非对称三栏；
- 图形：证据节点用不同几何形状，连线表达支持、冲突和缺失；
- 动效：只用于扫描进度、分数变化、节点聚焦和补证成功；
- 可访问性：正文对比度、键盘焦点、`prefers-reduced-motion` 和语义标签必须覆盖。

## 9. 错误与降级

- 空文件、不支持格式、超限文件显示就地错误；
- API Key 缺失不影响样例体验；
- 本地服务或模型不可用时显示原因和启动指引；
- Qwen 请求超时保留已完成的端侧结果；
- 导出失败时保留生成内容并允许复制；
- 不展示伪造的模型耗时、Token 数或联网状态。

## 10. 非目标

- 不做论文数据库检索或付费文献抓取；
- 不做多人协作、账号系统、数据库和云端部署后台；
- 不要求用户在初次体验前下载 4B 模型；
- 不宣称模型输出等同于学术审稿结论；
- 不在前端保存或展示完整 API Key。

## 11. 验证与交付

项目必须通过单元测试、组件测试、生产构建和实际浏览器桌面/移动端验证。最终 ZIP 包结构遵循赛事页面要求，包含作品展示、AI 实践佐证和体验说明，并额外提供封面、演示脚本、报名文案及评委问答。
